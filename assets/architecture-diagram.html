Glint Architecture

AI merge request summaries and release notes for self-hosted GitLab CE

Request flow

  • • 1. GitLab sends a webhook when a merge request is opened or a release is created
  • • 2. Glint authenticates it, validates the payload and answers 202 at once
  • • 3. It fetches the details and diff from the GitLab API
  • • 4. It sends them to the configured AI provider
  • • 5. It posts the summary as an MR comment, or writes the release description

AI providers

  • • Anthropic Claude by default
  • • Or any OpenAI-compatible server, chosen with AI_PROVIDER
  • • A local model (Ollama, LM Studio, vLLM) keeps all code on your network
  • • Both providers receive the same prompts
  • • Diffs are capped at 20,000 characters by default (MAX_DIFF_CHARS)

Security and operations

  • • Webhooks verified by HMAC signature or secret token, compared in constant time
  • • Private certificate authorities trusted without disabling TLS checks
  • • Tokens never written to logs; errors never expose internals
  • • Stateless: no database, one container, runs as a non-root user
  • • Structured JSON logs with a configurable level
